# LCD 冷启动显示异常调试记录

状态：[OPEN]

## 现象

设备直接掉电重启时，LCD 会闪烁一段时间，稳定后显示异常；经过 Keil 烧录流程后再启动，LCD 显示正常。

## 可验证假设

1. LCD 上电复位时序不足，初始化命令发送早于 LCD 电源或复位稳定。
2. DMA/FSMC 初始化顺序或外设初始状态在冷启动与 Keil 复位启动之间不同。
3. LVGL 缓冲区在 DMA 完成前被复用，导致像素数据异常。
4. NT35510 未被完整硬件复位，冷启动后控制器处于异常状态。
5. DMA 中断、传输完成状态或 LVGL 完成通知不同步。

## 当前阶段

已完成一次时序验证，尚未修改业务逻辑，也尚未添加运行时插桩。

## 新增证据

- 将 `lcd.c` 中 FSMC 初始化后的等待时间从 5 ms 调整为 200 ms 后，按 RESET 按键启动明显稳定。
- 进一步将相关等待调整为 1000 ms 后，完全掉电冷启动时，`led_toggle(LED_GREEN)` 对应的 LED 也出现反复点亮/熄灭。
- `lcd_init()` 当前静态搜索只有 `board_init()` 一处调用，但 LED 反复翻转说明 MCU 很可能发生了多次启动/复位，而不是同一次 `lcd_init()` 正常执行多次。
- 完全断电后重新上电也明显改善，但仍出现多次闪烁。
- 在未使用 DMA 的情况下也存在相同现象，因此 DMA 不是主要根因。

## 当前判断

- 假设 1（LCD 上电或复位时序不足）：得到支持，但尚未确认硬件复位脚时序。
- 假设 2（DMA/FSMC 初始化问题）：DMA 相关部分基本不支持；FSMC/上电时序仍需验证。
- 假设 3（DMA 缓冲区复用）：基本排除为主要根因。
- 假设 4（NT35510 未完整复位）：仍待确认。
- 假设 5（DMA 完成通知不同步）：基本排除为主要根因。

## 复现对照

- 冷启动：设备完全掉电后重新上电，观察 LCD 闪烁和最终画面。
- 烧录启动：通过 Keil 烧录后复位启动，观察最终画面。
